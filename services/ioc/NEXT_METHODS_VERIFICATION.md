There are four input families and seven output families. Including the separate

| Method | Source operation | Result |
| --- | --- | --- |
| `alienvault.domain_to_email` | `whois` | Concrete addresses from explicit email/emails WHOIS rows |
| `alienvault.url_to_url` | `http_scans` | Explicit Location destination from a stored HTTP redirect header |

## Why these methods

Both operations are generated by existing OTX report pages and each needs one
captured response. They reuse BrowserTransport, LookupClient, ObservationBuilder,
IOC normalization, normal receipts, cache scope, pacing and limits. Source-local
parsers live in `providers/otx_whois.py` and `providers/otx_http.py`; registration
and routes remain in `providers/alienvault.py`.

The browser routes do not need an API key. These new operations have no guessed
official-API backup; the previously implemented operations keep their existing
configured API fallbacks. No browser transport redesign, dependent-request
framework, source search, downloads or scan submissions were needed.

WHOIS emits source-listed contact addresses, including privacy relays whose
mailbox domain differs from the queried domain. It does not score ownership,
require mailbox-host equality or read arbitrary pulse/related-domain text.
Source identity, field types and concrete IOC formatting are checked locally.
Evidence facts are `{domain, email, field}` with `fact_type="whois_email"`.

URL-to-URL reads the stored scan's explicit HTTP status and Location field. It
supports absolute and relative destinations, rejects ambiguous/malformed headers
and ignores body/certificate URLs. It never visits the input URL or a returned
destination. Evidence uses the existing `url_link` facts and redirect kind.
Separate stored header rows retain their individual destinations and evidence;
they are not treated as a redirect chain. LookupClient deduplicates equal URL
outputs while preserving their source-row evidence. Duplicate Location fields
within a single header remain invalid, and valid URI apostrophes are preserved.

The existing validator checks method/result correctness. The workflow continues
to own overlap admission, graph changes and recovery. Source contacts and
redirects are lookup outputs; they do not bypass the workflow's decision.

Both parsers distinguish completed no-data results from malformed source data
and report truncated source containers as partial.

## Reproduce

Run from the IOC service directory using the existing environment:

```powershell
& 'D:\SEMESTERS\FYP\code\ioc-hunter\.venv\Scripts\python.exe' -B -m pytest tests -q --disable-warnings
& 'D:\SEMESTERS\FYP\code\ioc-hunter\.venv\Scripts\python.exe' -B tests/live_methods_audit.py --source alienvault --method alienvault.domain_to_email --method alienvault.url_to_url --max-pages 1 --domain python.org --url http://github.com/
```

The live audit creates a fresh store and sets `cache_ttl=0`. Each browser lookup
uses a new context. Audit manifests record only whether keys are configured,
never their values. Raw receipts and source bodies are retained for review.
