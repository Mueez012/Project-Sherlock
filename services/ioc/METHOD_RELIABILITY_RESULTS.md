# Method repair verification — 14 October 2026

**During the repair checks, 17 of the 21 implemented methods returned validated outputs. Three more completed with no applicable data; one remains unresolved (VirusTotal domain→URL).** These are sample results from iterative checks, not a claim that every input or anonymous access route is reliable. The previous audit's 10 positive methods remains historical evidence, not the current implementation's complete status.

The additional [real CTI report test](CTI_REPORT_LOOKUP_TEST.md) extracted `mypiltow.com` from row 670 and obtained 29 distinct validated IPv4 outputs across three sources. All eight domain-input methods received the extractor's actual IOC object and context.

## Primary access policy preserved

RapidDNS HTML pages and the paper's OTX/VirusTotal report-page interfaces remain primary. The browser opens those pages, activates report sections and captures the JSON generated by the website. No direct private API calls were added. Official OTX/VT APIs remain optional credentialed fallbacks. All live manifests below record **both API keys absent**; no authenticated browser state or scans were used.

## Implemented changes

- OTX website response paths are separate from public API paths. GUI URLs preserve observed colon escaping; IPv6 uses the working `/indicator/ip/` alias. URL general-report matching includes the observed extra-encoded variant. Subsequent live checks confirmed URL→domain and IPv6 country outputs; IPv6 DNS completed empty.
- VirusTotal IP response matching canonicalizes the IP identity, fixing escaped versus literal IPv6 colons without accepting another IOC or relationship. Later prefetched pages cannot replace the initial page.
- Browser acquisition listens before navigation, waits for a completed response body, and no longer exits on an unrelated table. Launch and result deadlines are separate. HTML fallback is limited to the requested OTX section and explicit readiness; unknown captures remain failures.
- OTX HTML recognizes `Query Type`, excludes unrelated sections, rejects outside-table loading spinners, and marks HTML coverage unverified. An empty table without a completed-empty signal is not a successful empty lookup.
- Provider not-found pages and bootstrap failures are classified. Provider XHR 429 stops acquisition; `Retry-After` is read case-insensitively. Failed captures and observed paths are retained. A transient browser deadline can retry once; successful retries retain their failed-attempt diagnostics.
- Country omission in a valid, bound IP response is `empty` with `outcome_reason: country_unavailable`. Missing object structure remains an error. Rejected candidates and partial results get explicit receipt reasons.
- Cache keys include an integration version and browser access-state fingerprint. Zero-observation responses have at most a five-minute TTL; old cache entries are isolated without deleting history.
- URL evidence locators match nested fields. A final URL by itself does not establish an immediate redirect edge.
- The opt-in live audit stops its source batch on rate limiting. Added real captured-schema fixtures and controlled browser regression tests.
- OTX domain→URL pagination clicks the verified Next control in the same session. A live two-page test returned 11 validated URLs. Paginated GUI reads start live rather than relying on cached pages without browser state; no private next URL is called directly.
