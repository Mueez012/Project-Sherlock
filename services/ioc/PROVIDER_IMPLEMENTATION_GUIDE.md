# Provider implementation practices

The project's primary sources are the report-page interfaces listed in the paper:

| Source | Primary route |
| --- | --- |
| RapidDNS | `https://rapiddns.io/s/[IOC-Value]#result` and the provider's linked result pages |
| AlienVault / OTX | `https://otx.alienvault.com/indicator/[IOC-Type]/[IOC-Value]` |
| VirusTotal | `https://www.virustotal.com/gui/[IOC-Type]/[IOC-Value]/details` and its related report tabs |

Use the appropriate tab/result link for the operation. A website JSON response is data generated by that report page, not a replacement primary integration. Official API calls are optional fallbacks only, using configured credentials and supported entitlements. Preserve this distinction in code and documentation.

## Start with an observed provider contract

Before enabling a method, inspect the real report for the proposed input type and operation. Record the GUI link format, required tab, actual response URL, body shape, pagination and access state. Test URL and IPv6 escaping explicitly. OTX's public API path and website path differ; VirusTotal IP response paths can use literal colons even when navigation uses escaped colons.

Do not assume that a catalogue declaration, public API capability, or another project's endpoint proves that our anonymous website route works. Retain a dated raw capture and a small representative fixture. Label synthetic fixtures separately.

## Keep responsibilities clear

| Component | Responsibility |
| --- | --- |
| `providers/<source>.py` | Methods, GUI/API routes, accepted response paths, source-specific schemas and error markers |
| `transport/browser.py` | Open provider page, activate tab, capture completed response, deadline and diagnostics |
| `transport/http.py` | Public HTML retrieval and authorized optional API requests |
| `providers/common.py` | Shared field conversion, normalization and evidence construction |
| `validation.py` | Independently check ontology and proof for exact edge endpoints |
| `lookup.py` | Limits, retries, cache, receipts and validated output list |
| Future algorithm/workflow | Select methods, evaluate expansion, mutate graph and keep exploration state |

The method interface remains `IOC -> list[IOC]`. Consult its receipt for status, reasons and provenance. MCP exposes that interface; it is not a scraping engine or an alternative readiness mechanism.

## Browser acquisition rules

1. Register listeners before navigation or a tab action. Read response bodies after `requestfinished`, not inside a response callback that can still be waiting on the body.
2. Match provider host, operation and IOC identity. Enumerate observed URL-valued path variants; never recursively decode arbitrary paths. Canonicalize typed IP addresses, and reject other IPs, other operations and prefetched later pages.
3. Do not stop because any table exists. WHOIS may render before DNS. Prefer the requested completed JSON response. An HTML fallback must identify the requested section, exclude its loading state, and have actual rows or a completed-empty signal.
4. A deadline is not an empty answer. Retain the unfinished page and classify the failure. Current defaults are a 30-second browser launch timeout and a separate 60-second navigation/result deadline; cleanup adds overhead.
5. Distinguish relevant failures from optional widgets. An anonymous VirusTotal `/ui/me` 401 does not invalidate a successful DNS response. A provider XHR 429 stops acquisition and sets a cooldown; preserve `Retry-After` case-insensitively.
6. Never visit the returned IOC's own URL or submit scans as part of enrichment. Stay on provider report pages.

Playwright documents response events/waits and discourages treating whole-page network-idle as application readiness. [Network documentation](https://playwright.dev/python/docs/network), [load-state documentation](https://playwright.dev/python/docs/api/class-page#page-wait-for-load-state)

## Parsing and relationship proof

Parse source fields, not every IOC-looking string on the page. Unrelated pulses, WHOIS contacts, scripts and advertisements are not proof of the requested relationship. For structured JSON, map only the relevant array/object. For OTX HTML, use the operation's section and recognize the actual `Query Type` header.

Validate the response envelope and identity before deciding an optional field is unavailable. An IP object without country produces `country_unavailable`; a missing IP object is a parse error. Preserve `all_candidates_rejected` separately from a provider response with no matching records.

Bind DNS to exact hostname, IP and A/AAAA type. A record for www.example.com does not prove a DNS edge for example.com. Preserve direct URL-link evidence and ordered redirect-chain semantics; a final destination alone does not establish an immediate hop. Evidence locators must address the real nested field, with the original snapshot digest and source.

An LLM may summarize cited context. It must not fill missing fields, invent edges or override the validator. The graph algorithm decides expansion success after consuming validated results.

## Limits, cache and pagination

- Bound retries and log them. Initial-page browser deadline failures get at most one extra attempt; existing HTTP/network/server limits remain. Do not retry a failed next-page click, which could skip data. Do not retry schema errors, explicit not-found pages or access denials as transient loading.
- Source pacing and cooldown are per client. The shared store counts top-level retrieval attempts, not every page asset/XHR. An automatic runner must coordinate all its clients/workers; do not launch parallel clients for the same source to work around cooldowns.
- Stop a live audit source batch on 429. A follow-up run is a separate decision after cooldown; do not keep retrying until one response succeeds and hide the preceding failures.
- Version cache identity when acquisition/parsing assumptions change. Separate authenticated browser state and API credentials without exporting secrets. Current positive cache TTL is 24 hours; zero-observation responses are capped at five minutes. Preserve immutable historical snapshots and receipts.
- Pagination must stay bound to the same IOC and operation. Use the provider's verified UI next action in the same session; do not convert a captured private next link into a direct API request. Until that action is implemented and verified, return `partial` with `browser_pagination_not_verified` or `page_limit`.
- OTX domain→URL now has a verified Next selector and same-session pagination. Multi-page GUI reads start live because cached raw pages cannot restore the page's navigation state. Single-page cache use remains available; all responses still have immutable snapshots. VirusTotal next-page controls remain unverified.
- Reaching page/output/access limits is not complete coverage. A successfully parsed response can still be partial.

MISP's VirusTotal adapter provides a useful example of provider-specific field mappings and bounded relationship iterators. Its endpoint choices and broader graph relationships should not be copied without checking our access policy and ontology. ## Minimum acceptance checklist

Before calling a new method ready:

- Add positive and negative parser tests from observed schemas, including an unrelated IOC that must be rejected.
- Test the real browser with intercepted responses: unrelated table first, delayed result, spinner/empty placeholder, access/rate errors, and a missing response.
- Test endpoint identity, IPv6/URL encoding, first-page versus prefetch behavior, and cache/access isolation.
- Run live checks with retained raw responses and explicit credentials/access mode. Use multiple inputs and repeated runs before claiming broad reliability; one positive sample only establishes that sample.
- Report **implemented**, **offline tested**, **live positive**, **confirmed no-data**, **partial**, and **blocked/unverified** separately. Preserve original failures and note changes made between runs.
- Ensure the existing extraction/lookup/MCP tests still pass and update source documentation and the live evidence matrix.

Current evidence and unresolved work are tracked in [the repair verification report](METHOD_RELIABILITY_RESULTS.md). The original plan remains in [METHOD_RELIABILITY_REPAIR_PLAN.md](METHOD_RELIABILITY_REPAIR_PLAN.md).

Include a real-report integration check as well: use `extract_report`, select an actual returned IOC with its context, and pass that object to lookup. Save the report hash, extraction result and receipts together. [The reproducible CTI test](CTI_REPORT_LOOKUP_TEST.md) demonstrates this without introducing algorithm or graph state into provider code.
